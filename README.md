# mcmotorolla — дневник пройденных игр

Публичный сайт-дневник стримера [mcmotorolla](https://www.twitch.tv/mcmotorolla) (Twitch ·
[Telegram](https://t.me/mcmotoroller)): список пройденных игр
с оценкой от 1 до 10 и заметками о прохождении. Читать может любой, редактировать — только владелец
через скрытую страницу `/admin`.

Код: [github.com/evgeniykolenkin/mcmotorolla](https://github.com/evgeniykolenkin/mcmotorolla) (MIT).

## Страницы

| Путь | Что это |
| --- | --- |
| `/` | главная: статистика, поиск, сортировка, сетка игр |
| `/game/:slug` | страница игры: оценка, вывод, заметки о прохождении |

## Поиск и сортировка

- Поиск — по названию, жанру, короткому выводу и тексту отзыва; регистр и лишние пробелы
  по краям не важны.
- Сортировка (один селект): «Сначала новые» (по дате прохождения), «По оценке», «По названию»,
  «По прохождению».
- «По прохождению» — не фильтр, а порядок: пройдена → прохожу сейчас → брошена, внутри группы
  новые сверху. Ничего не скрывается; записи без статуса считаются пройденными.
- Поиск и сортировка работают вместе; «Сбросить» появляется, когда поиск непустой или
  сортировка не «Сначала новые», и возвращает оба значения к дефолту.
- На главной видны только опубликованные игры (черновики — в `/admin`).
- Фильтр платформ на главной временно скрыт (код с комментарием оставлен в
  `GamesToolbar.vue`); платформа по-прежнему выбирается в форме игры.

## Данные и авторизация (Supabase)

Игры хранятся в Postgres (Supabase), вход владельца — Supabase Auth (email + пароль).
Режим выбирается автоматически: если в `.env.local` заполнены `VITE_SUPABASE_URL` и
`VITE_SUPABASE_ANON_KEY` — работает Supabase, иначе приложение откатывается в локальный
режим (localStorage), чтобы интерфейс можно было смотреть без бэкенда.

```bash
cp .env.example .env.local   # Windows: Copy-Item .env.example .env.local
```

| Переменная | Что это |
| --- | --- |
| `VITE_SUPABASE_URL` | Project URL вида `https://<ref>.supabase.co` (без `/rest/v1/`) |
| `VITE_SUPABASE_ANON_KEY` | publishable key `sb_publishable_...` (не `sb_secret_...`!) |
| `VITE_OWNER_EMAIL` | email владельца; если пусто — поле email показывается в форме входа |
| `VITE_OWNER_PASSWORD` | только для локального режима (когда Supabase не настроен) |

Компоненты общаются с данными только через фасад `src/services/gamesRepository.js`
(`list / getBySlug / create / update / remove`), поэтому не знают, откуда приходят записи.

### Настройка Supabase (один раз)

1. Проект Supabase → **Project Settings → API**: скопировать Project URL и publishable key
   в `.env.local` и в Vercel.
2. **SQL Editor** → выполнить `supabase/0001_games.sql`: таблица `games`, индексы, триггер
   `updated_at`, RLS-политики и гранты. Скрипт идемпотентен, его можно запускать повторно.
   Затем — `supabase/0002_game_meta.sql`: колонки `release_year` и `steam_app_id` под
   автозаполнение из Steam (плюс разовая чистка старых пустых значений). Пока этот скрипт
   не применён, приложение продолжает сохранять игры, но без года и appid.
   Затем — `supabase/0003_site_settings_and_media.sql`: таблица `site_settings` для
   редактируемых текстов и публичный бакет Storage `media` для аватарки и фона главной.
   **Этот скрипт нужно применить до деплоя кода**, который его использует: без таблицы
   карандашики покажут ошибку сохранения, а без бакета не загрузится картинка.
3. **Authentication → Users → Add user**: email владельца + пароль, включить
   **Auto Confirm User**.
4. **Authentication → Sign In / Providers → Email**: выключить **Allow new users to sign up** —
   регистрация закрыта, пользователь только один.
5. Проверка: `/admin` → вход по email и паролю → «Добавить игру» → начать вводить название,
   выбрать подсказку Steam, сохранить. Запись появляется на главной.
6. Проверка защиты (по желанию, из терминала): анонимный `GET /rest/v1/games` возвращает
   только опубликованные строки, а `POST` с publishable key — `401 permission denied`.
7. Проверка правок с сайта: на главной войти в `/admin`, вернуться на `/`, нажать карандашик
   у заголовка → сохранить → обновить страницу. Текст должен остаться. То же с аватаркой
   (камера на аватаре) и фоном (кнопка «Фон» в углу главной секции).

### Файлы и картинки (Storage)

`supabase/0003_site_settings_and_media.sql` создаёт публичный бакет `media` (лимит 5 МБ на
файл, типы `image/jpeg`, `image/png`, `image/webp`, `image/avif`) и четыре политики на
`storage.objects`: читают все, загружает, перезаписывает и удаляет только вошедший
владелец — и только в папках `avatar/` и `hero/`.

- Если бакет не появился в **Storage**, создайте его вручную (`media`, Public) и добавьте
  политики из конца `0003`-скрипта.
- Free-тариф: 1 ГБ Storage и 5 ГБ трафика в месяц. Два файла по ~200 КБ плюс годовое
  кеширование в браузере (`cacheControl` 1 год) укладываются в лимиты с запасом.
- Сжатие делается в браузере до загрузки: аватар до 512 px, фон до 1920 px, WebP. Файл
  с телефона на 4 МБ превращается в ~200 КБ, поэтому телефонный интернет не страдает.

### Что защищено и как

| Операция | Кто | Условие |
| --- | --- | --- |
| `select` | все | только `published = true` |
| `select` | владелец | все свои записи, включая черновики |
| `insert / update / delete` | вошедший владелец | `owner_id = auth.uid()` |

Publishable key публичный — доступ к строкам ограничивает база через RLS. Secret key
(`sb_secret_...` / `service_role`) в браузерном коде не используется никогда.

## Доступ владельца

Владелец в проекте один: каждая запись привязана к `owner_id`, поэтому второй аккаунт
не увидит и не сможет править игры первого. Регистрация закрыта (`disable_signup`),
пароль знает только владелец.

- Пароль не хранится в открытом виде: Supabase держит bcrypt-хэш
  (`auth.users.encrypted_password`). Посмотреть пароль нельзя ни в Dashboard, ни через API.
- Практика: пароль лежит в менеджере паролей (Bitwarden, 1Password, браузер), а другу
  передаётся личным каналом, не в общем чате.
- Смена пароля из интерфейса `/admin` намеренно не сделана — при необходимости добавляется
  через `supabase.auth.updateUser({ password })`.
- Если пароль забыт или скомпрометирован: **Authentication → Users → ⋯ → Reset password**
  (письмо со ссылкой; встроенный SMTP free-тарифа ограничен по частоте) либо сброс через
  Admin API с secret key — только с локальной машины, ключ не попадает ни в Vercel, ни в бандл.

## Редактирование текстов и картинок

Всё, что раньше правилось только в коде, владелец меняет прямо на сайте: после входа в
`/admin` рядом с текстами главной и подвала появляется карандашик, у аватарки — камера,
у главной секции — кнопка «Фон». В шапке правится **только аватарка**: ник и подпись
остаются в `src/config/site.js`, чтобы шапка всегда выглядела одинаково (сам бренд —
аватарка и ник — ведёт на главную).

| Что | Где | Ключ в `site_settings` |
| --- | --- | --- |
| Аватарка | шапка, камера поверх аватара | `brand.avatarUrl` |
| Надпись, заголовок и подзаголовок | главная | `hero.eyebrow`, `hero.title`, `hero.subtitle` |
| Подпись, ссылка и иконка основной кнопки | главная, карандаш у кнопки | `hero.primaryLabel`, `hero.primaryUrl`, `hero.primaryIcon` |
| То же для второй кнопки | главная | `hero.secondaryLabel`, `hero.secondaryUrl`, `hero.secondaryIcon` |
| Добавленные кнопки (до 4) | главная, «+ Кнопка» | `hero.extraButtons` (JSON-массив) |
| Фон главной секции и его кадрирование | главная, «Фон» | `hero.bgUrl`, `hero.bgPosition` (`top` / `center` / `bottom`) |
| Текст в подвале | подвал, карандаш рядом с текстом | `footer.text` |

- Кнопками в главной секции управляет одно окно `HeroButtonDialog`: подпись (до 40 знаков),
  ссылка (только `http(s)`), иконка из набора PrimeIcons и живой предпросмотр. У добавленных
  кнопок есть «Удалить», у двух базовых — «Как было» (вернуть значения из кода).
- Пустая ссылка у базовой кнопки = кнопка скрыта: посетители её не видят, а владелец видит
  пунктирную заглушку «…: скрыта» и может вернуть кнопку тем же окном.
- Ссылки и иконки из базы проверяются при чтении: не-`http(s)` ссылка не превратится в
  `javascript:`, незнакомая иконка заменится на `pi pi-external-link`, битый JSON добавленных
  кнопок — на пустой список.
- Положение фона меняется в диалоге «Фон» (Верх / Центр / Низ) и сохраняется сразу —
  картинка та же, меняется только `object-position`.
- Тексты живут в таблице `public.site_settings` (одна строка = одно поле): читают все,
  пишет только вошедший владелец — политики те же, что у `games`.
- Значения по умолчанию — в `src/config/content.js`. Если база недоступна или ключа ещё
  нет, показываются они, поэтому шапка и герой никогда не остаются пустыми. Кнопка
  «Как было» в попапе удаляет правку и возвращает дефолт; пустое значение у текстов и
  подписей тоже означает «показывать дефолт».
- Файлы лежат в публичном бакете `media` (папки `avatar/` и `hero/`), см. раздел
  «Файлы и картинки (Storage)» выше.
- В локальном режиме (без Supabase) загрузка файлов выключена — диалог предложит вставить
  ссылку на картинку, а тексты сохранятся в `localStorage` (`mcmotorolla.site.v1`).
- Пока настройки грузятся, в главной секции и на месте аватарки видны скелетоны: дефолтные
  тексты не мигают. Если база ответила ошибкой, скелетоны снимаются и сразу показываются
  дефолты из `src/config/content.js`.
- Соцсети живут кнопками в главной секции и ссылками в подвале: в шапке остались
  аватарка, «Игры», переключатель темы и вход в панель.
- Кнопка «Добавить» из шапки убрана: добавление игры — через «Панель владельца» на главной
  или пустое состояние списка.

## Локальный режим (без Supabase)

Если переменные Supabase пустые, данные лежат в `localStorage` браузера
(`mcmotorolla.games.v1`) и дневник стартует пустым — никаких демо-записей нет. Вход — пароль
из `VITE_OWNER_PASSWORD` (по умолчанию `admin`). Это **не безопасность**: пароль попадает
в бандл. Режим нужен только для разработки интерфейса без бэкенда.

## Оценки

Оценка — целое число 1–10, отображается цветным бейджем:

- 9–10 — зелёный («великолепно»)
- 7–8 — салатовый («хорошо»)
- 5–6 — оранжевый («средне»)
- 1–4 — красный («слабо»)

На бейдже, в карточке статистики и в слайдере формы оценка пишется с пробелами —
«8 / 10», чтобы дробь читалась как дробь, а не как «8/10».

## Markdown в отзывах

Поле «Как проходил» понимает markdown — единственное поле с разметкой, вердикт и остальные
поля остаются простым текстом.

| Написать | Получится |
| --- | --- |
| `# Заголовок` | заголовок 1 уровня |
| `## Подзаголовок` | заголовок 2 уровня (уровни `#`…`######` — от крупного к мелкому) |
| `### Мелкий` | заголовок 3 уровня |
| `**жирный**` | **жирный** |
| `*курсив*` | *курсив* |
| `~~зачёркнутый~~` | ~~зачёркнутый~~ (markdown-it рендерит в `<s>`) |
| `++подчёркнутый++` | подчёркнутый (расширение проекта, рендерится в `<u>`) |
| `` `код` `` | код в строке |
| `- пункт` | маркированный список |
| `1. пункт` | нумерованный список |
| `  - вложенный` | вложенный список (отступ 2 пробела) |
| `- [ ] дело` | чек-лист с пустым квадратиком |
| `- [x] дело` | чек-лист с отмеченным квадратиком |
| `> цитата` | цитата |
| `[текст](https://…)` | ссылка |
| `https://…` | голая ссылка сама становится кликабельной |
| `---` | разделитель |
| `\*` | экранирование: показать символ, не включая разметку |

- Пустая строка между блоками = новый абзац, одиночный перенос строки тоже сохраняется.
- В форме есть кнопка «?» со шпаргалкой (синтаксис + живой пример каждого элемента) и
  переключатель «Текст / Предпросмотр».
- Чек-листы и подчёркивание сделаны двумя маленькими правилами в `src/utils/markdown.js`
  (без новых зависимостей): `- [ ]`/`- [x]` превращаются в `span.md-task`, а `++текст++`
  в `<u>` (внутри работает и другая строчная разметка, например `++**жирный**++`).
  Правило подчёркивания не срабатывает, если за закрывающими `++` идёт слово или
  плюс, поэтому «C++» остаётся текстом.
- Не поддерживается: картинки `![](…)` и сырой HTML — он вырезается санитайзером.
- Сырой HTML не исполняется: `markdown-it` работает с `html: false`, а результат перед
  вставкой дополнительно чистит `DOMPurify`. Внешние ссылки открываются в новой вкладке
  с `rel="noopener noreferrer"`.
- Карточки на главной показывают вердикт, поэтому разметка видна только на странице игры.

## Автозаполнение из Steam

Форма игры (`/admin` → «Добавить игру») ищет название в Steam и подставляет **только
метаданные**: название, обложку 600×900, жанры и год выхода. Оценку, часы, вердикт и
описание владелец пишет сам — тексты Steam в дневник не попадают.

- Публичный Steam Store API не отдаёт CORS-заголовки, поэтому браузер ходит в свой прокси
  `GET /api/steam?action=search|game` (`api/steam.js` + `api/_steamClient.js`), ключи не нужны.
- В `npm run dev` Vercel-функций нет: тот же `/api/steam` обслуживает middleware
  `steamDevApi` из `vite.config.js`, так что код Steam-клиента один.
- Ответы кешируются: на CDN Vercel — неделя, в браузере — 10 минут (частые запросы к Steam
  начинают отдавать пустые ответы).
- Регион магазина в запросах — `cc=US` (в RU-каталоге нет части игр, например The Witcher 3),
  язык — `l=russian`, поэтому названия и жанры русские.
- Если Steam недоступен, форма остаётся рабочей: любое поле можно заполнить вручную.
- Своя обложка заменяет steam-овскую, кнопка «Убрать» очищает ссылку.
- В форме ссылки на магазин нет — она на странице игры, справа от названия (строится из
  `steam_app_id`, показывается только если он есть). Стримеру в форме она не мешает.
- Модалки (форма игры и диалог картинки) закрываются кликом по затемнённому фону; пока идёт
  сохранение или загрузка файла, клик по фону игнорируется, чтобы не потерять данные.

### Первый деплой на Vercel (один раз)

1. [vercel.com](https://vercel.com) → **Add New → Project → Import Git Repository** →
   `evgeniykolenkin/mcmotorolla`.
2. Framework Preset: **Vite**. Build Command `npm run build`, Output Directory `dist` —
   уже зафиксированы в `vercel.json`, менять не нужно.
3. **Project Settings → Environment Variables** (добавить для Production и Preview):
   - `VITE_SUPABASE_URL` — Project URL Supabase;
   - `VITE_SUPABASE_ANON_KEY` — publishable key (`sb_publishable_...`);

4. Deploy. Прод: <https://mcmotorolla.vercel.app> (в РФ `*.vercel.app` может требовать VPN).
5. Смоук-тест прода:

   - подвал: карандаш рядом с текстом меняет подпись; бренд в шапке ведёт на `/`;
   - прямой заход на `/game/elden-ring` — не 404 (работает SPA-rewrite);
   - `/admin` — вход владельца, создание и удаление записи, перезагрузка страницы;

  `.github/workflows/supabase-keepalive.yml` (см. ниже).

## Keep-alive Supabase

Free-проект Supabase засыпает после ~7 дней без запросов, и первый визит пользователя
ждёт холодный старт. Workflow `.github/workflows/supabase-keepalive.yml` раз в сутки
(04:17 UTC) делает `GET /rest/v1/games?select=id&limit=1` и падает, если ответ не `200`, —
так сбой виден в GitHub Actions.

- Ручной запуск: **Actions → Supabase keep-alive → Run workflow**.
- URL и publishable key зашиты как значения по умолчанию (они публичны и всё равно попадают
  в бандл); при желании переопределяются repository variable `SUPABASE_URL` и
  secret `SUPABASE_ANON_KEY` без правки файла.
- Расписание GitHub может задерживать запуск на несколько минут — для keep-alive это не важно.
